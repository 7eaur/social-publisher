# تقرير تدقيق الإصدار الشامل — Social Publisher

**التاريخ:** 2026-10-17  
**المستودع:** 7eaur/social-publisher  
**مرجع الفحص:** build/secure-onboarding-dashboard-20261017  
**النطاق:** مراجعة الكود والبنية واختبارات GitHub Actions وربط مكونات النشر، وجرد خدمات Railway المتصلة.  
**قرار الإصدار:** **قبول كود التطوير فقط؛ رفض اعتماد نظام نشر إنتاجي مكتمل أو تفعيل النشر الحي حاليًا.**

## 1) ما تأكدنا منه

- التطبيق مستقل؛ Postiz مرجع معماري لا نسخة منسوخة.
- Backend: Fastify مع PostgreSQL وترحيلات 0001–0007 وقواعد القفل الذري وقائمة انتظار النشر.
- صلاحيات أساسية وتشفير معلومات الربط وحفظها دون إظهارها مرة أخرى من واجهات القراءة.
- صفحات إدارة RTL: النظرة العامة، المصادر، المسارات، المكتبة، التقويم، التهيئة، إعدادات الرموز.
- اختبارات بيئة حسابات وهمية: TypeScript وJavaScript واختبارات وحدات وPostgreSQL وAPI وتيليجرام.
- قاعدة البيانات تُفحص حاليًا في readiness من حيث **تطبيق آخر ترحيل مطلوب**، لا مجرد توفر الاتصال.
- Runtime الإنتاجي يستمع على عنوان عام للخدمة، مع بقاء live publishing مغلقًا.
- المستودع كان Public في الفحص؛ **لا تُدخل أسرارًا حقيقية إلى Git أو Pull Requests تحت أي ظرف.**

## 3) سياسة الدمج والنشر

- يمكن دمج **كود الأساس التطويري** في main بعد اجتياز بوابة CI؛ الدمج ليس شهادة جاهزية إنتاجية.
- لا يجوز نشر خدمة ناطقة للعامة دون PostgreSQL مهاجرة ومفتاح تشفير وADMIN bootstrap وحدود النشر وتعريف بيئة الاستضافة.
- **يمنع تشغيل live publishing** إلى أن تغلق كل فجوات P0 ويتحقق الفريق من حسابات اختبار مصرح بها.
- لا توجد جلسات أو رموز حسابات حقيقية ضمن الملفات، ولم يتم طلبها من المستخدم في المحادثة.
- اختيار مساحة Railway مرتبط بحساب من حسابات متصلة عديدة ويجب تأكيده قبل أي إنشاء خدمة مدفوع/تعديل في بيئة غير مسماة.
