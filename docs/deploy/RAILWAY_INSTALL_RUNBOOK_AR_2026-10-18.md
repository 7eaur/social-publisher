# دليل تجهيز استضافة Social Publisher — مرحلة التجربة

**تاريخ:** 2026-10-18  
**الفرع:** `deploy/railway-staging-bootstrap-20261018`  
**الحالة:** تجهيز البنية والتثبيت الأولي، **لا يوجد نشر حي مؤكّد**.

## قبل إنشاء خدمة

- لا تستخدم استضافة مشروع Himma أو tlebotpost؛ أنشئ مشروع Railway جديدًا ومستقلًا تحت الحساب الذي يختاره صاحب المشروع.
- يحتوي GitHub حاليًا على مستودع **Public**؛ يجب تحويله إلى **Private** قبل تهيئة أي جلسات أو معلومات حساسة. لا تسجل أي رموز في GitHub أو ملف .env.
- إذا كان الحساب متصلًا بأكثر من Railway Workspace فلا نخمن أي حساب لعمليات الإنشاء/المدفوعات.
- انشر خادم API+Dashboard فقط في بيئة **staging**، مع `LIVE_PUBLISHING_ENABLED=false`.
- PostgreSQL ضمن نفس المشروع، بلا اتصال TCP عام إن لم يلزم.
- لا يوجد مُرسل منشورات حقيقي يعمل بعد؛ لا تدّعِ اكتمال النشر التلقائي.

## تشغيل قاعدة البيانات والتطبيق

- Railway PostgreSQL ينشر `DATABASE_URL` في البيئة. استخدم مرجع الخدمة الداخلي، عادة `${{Postgres.DATABASE_URL}}`.
- اتصال PostgreSQL عبر `.railway.internal` يسلك شبكة Railway الخاصة المشفرة؛ الاتصالات الخارجية في إنتاج حقيقي تتطلب `sslmode=verify-full` وشهادة صحيحة.
- `railway.json` يشغّل تثبيت الاعتماديات، ثم `npm run db:migrate` قبل إقلاع API، ثم `npm run api:start` وفحص `/health/ready`.
- إعدادات أساسية عبر **Railway Variables**:
  - `NODE_ENV=production`
  - `DATABASE_URL=${{Postgres.DATABASE_URL}}` عند تسمية قاعدة البيانات Postgres
  - `APP_ORIGIN=https://<railway-domain>` دومين الخدمة الحقيقي دون / أخيرة
  - `LIVE_PUBLISHING_ENABLED=false`
  - `LOGIN_THROTTLE_PEPPER` قيمة عشوائية عالية الإنتروبيا طويلة لا تقل عن 32 حرفًا
  - `SECRETS_ENCRYPTION_KEY` مفتاح عشوائي من 32 بايت بصيغة Base64
  - `INSTALL_SETUP_TOKEN` رمز تثبيت لمرة واحدة (32 بايت عشوائي بصيغة Base64URL بدون =، 43 حرفًا).
- لا تطبع مفاتيح التشفير أو الرمز في السجلات ولا ترفقها في دردشة.

## أول زيارة للداشبورد

1. تأكد أن `/health/ready` يعيد `{"status":"ready"}`.
2. افتح دومين HTTPS الخاص بالخدمة. إذا لم يوجد مدير، ستظهر شاشة **إنشاء المدير الأول**.
3. ادخل رمز التثبيت من مدير أسرار Railway وبريد المدير وكلمة مرور قوية من الواجهة.
4. تُحفظ كلمة المرور باستخدام scrypt ويُنشأ المدير مرة واحدة تحت قفل قاعدة بيانات ذري.
5. احذف `INSTALL_SETUP_TOKEN` من متغيرات Railway فورًا بعد إكمال التثبيت؛ لا تعتمد على إخفائه وحده.
6. سجّل الدخول، ثم جهّز مصادر Telegram والحسابات من **الإعدادات والأمان**. تخزين البيانات مشفر، لكن لا يفعّل النشر أو يؤكد صحة الحسابات.
7. لا تفعل خدمة Worker للنشر الخارجي حتى اكتمال الاستقبال/Media/Meta واختبار الحسابات المصرح بها.

## تحقق قبل الإعلان عن الإطلاق

- تأكد أن كلمة مرور المدير غير موجودة في Variables/Git.
- تحقق من HTTPS وSecure/HttpOnly/SameSite، وفشل CSRF الخاطئ والـOrigin غير المصرح.
- افحص migrations 0001–0007 وتوفر التشفير واستعادة البيانات بعد إعادة تشغيل الخدمة.
- جرّب تسجيل الدخول والخروج وحفظ/حذف إعداد تجريبي.
- افحص مظهر الداشبورد في الهاتف والكمبيوتر.
- لا تصف النظام بأنه منشور لنشر تلقائي حي قبل إغلاق فجوات P0 الموثقة بـ`docs/qa/COMPREHENSIVE_RELEASE_AUDIT_AR_2026-10-17.md`.
